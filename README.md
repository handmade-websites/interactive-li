# interactive.li

The public site for Interactive.li, served by GitHub Pages at
<https://interactive.li>.

Five pages, one build script, no dependencies. The repository *is* the deployed
site: whatever is committed here is what visitors get. The one thing that is
generated — the German and French home pages — is generated into the repository
and committed alongside everything else.

```
index.html         home page in English, and the template the other two are built from
de/index.html      generated by build.py — do not edit
fr/index.html      generated by build.py — do not edit
poster.html        notes and references for the 2025 Klimatag poster (EN only)
404.html           served by Pages for any address that does not exist
build.py           writes de/ and fr/ from index.html + the locale files
i18n/{de,fr}.json  the translated copy; English lives in index.html itself
css/style.css      the whole design; one stylesheet for all five pages
css/fonts.css      @font-face rules for the self-hosted fonts
fonts/             self-hosted woff2; no third-party requests, ever
pdf/               session booklets linked from the home page
```

No page runs a script for anything but the year in the footer.

## Why each language is a directory

A static host cannot vary a response by query string. The earlier version of
this site translated in the browser and advertised `?lang=de` and `?lang=fr` as
separate URLs, which meant Google requested three addresses and received three
byte-identical English pages, each carrying a canonical pointing at `/`. It
folded them together and reported the contradiction — the sitemap claimed three
pages, the markup claimed one.

`/de/` and `/fr/` are real files with the translated copy in the markup. Each
canonicalises to itself, all three list one another in `hreflang`, and the
sitemap says the same thing the pages do. That agreement is the entire
requirement; without it the annotations are discarded.

Building the copy in also removed the reason the four runtime scripts existed,
and with them the moment where a German visitor saw English before the locale
file landed.

## How the two halves fit together

`index.html` owns the **structure** — which elements exist and in what order —
and the **English words**, inline, where they are the page's real copy rather
than a placeholder. `i18n/de.json` and `i18n/fr.json` own the translations.
`build.py` matches one to the other by the `data-i18n` path on each element:

```html
<p class="exp-hook" data-i18n="experiences.items.beyond_coal.hook">English text</p>
```

So: **to change what appears or in what order, or to change English wording,
edit `index.html`. To change a translation, edit the locale file.** Then run:

```bash
python3 build.py
```

`poster.html` and `404.html` are English only and hold their text inline.

Every `data-i18n` path must exist in both locale files. A missing one leaves
English on the translated page, so `build.py` names it and exits non-zero
rather than shipping it quietly. It also fails on a path in `index.html` that
is relative to the page — those resolve against `/de/` and 404 — and on markup
nested inside a translated element, since `data-i18n` replaces an element's
whole text and cannot preserve an anchor part-way through a sentence.

## Adding a simulation

**1. Add an `<li>` to the list in `index.html`.** Copy an existing one and give
it a new slug — `water_wars` below. The slug is yours to pick; it just has to
match between the markup and the locale files.

```html
<li class="exp">
  <h3 class="exp-title" data-i18n="experiences.items.water_wars.title">Water Wars</h3>
  <p class="exp-hook" data-i18n="experiences.items.water_wars.hook">Allocate a shrinking river between farms, cities and a delta.</p>
</li>
```

**2. Add the same slug to `experiences.items` in both locale files:**

```json
"water_wars": {
  "title": "Water Wars",
  "hook": "Allocate a shrinking river between farms, cities and a delta."
}
```

**3. Run `python3 build.py`** and commit `de/index.html` and `fr/index.html`
along with your edits.

Skip step 2 and the build fails, naming the slug. To publish a session before
its translations are ready, give it the English string in both locale files
deliberately — the point is that English on a German page is a decision
somebody made, not something that happened.

**To reorder**, move the `<li>`. **To remove one**, delete the `<li>`; the
orphaned locale entries do no harm, but are worth deleting too.

### Sessions with a booklet

Wrap the title in a link and add a badge. The badge is hidden from screen
readers and the format goes into `link_label` instead, so the link's spoken
name carries it once rather than twice:

```html
<h3 class="exp-title"><a href="/pdf/generations.pdf"
   data-i18n="experiences.items.generations.title"
   data-i18n-attr="aria-label:experiences.items.generations.link_label"
   aria-label="Generations (PDF, English)">Generations</a><span class="exp-tag"
   data-i18n="experiences.items.generations.pdf_label" aria-hidden="true">PDF, English</span></h3>
```

```json
"generations": {
  "title": "Generations",
  "hook": "…",
  "pdf_label": "PDF, English",
  "link_label": "Generations (PDF, English)"
}
```

`pdf_label` is how a booklet offered in one language only says so on its badge
— it reads "PDF, Englisch" on the German page.

## Adding a language

1. Add `i18n/xx.json`, with the same keys as an existing locale file.
2. Add the code to `TARGET_LANGUAGES` in `build.py`, and a locale to
   `OG_LOCALES` there (Open Graph wants `xx_XX`).
3. Add a `.lang-link` to the switcher and an `hreflang` link in `index.html`,
   pointing at `/xx/`.
4. Add the URL and its alternates to `sitemap.xml`, and add the same alternate
   to the entries already there — every page lists every variant.
5. Run `python3 build.py`.

## Previewing

Build, then open a server at the repository root — `file://` will not do,
because the pages use root-absolute paths:

```bash
python3 build.py && python3 -m http.server 8000
```

Then <http://localhost:8000/>, `/de/` and `/fr/`.

## Things worth knowing before changing them

- **`de/index.html` and `fr/index.html` are generated.** Edits to them are lost
  on the next build. Change `index.html` or a locale file instead. They are
  committed rather than built on deploy because Pages serves the repository as
  it stands; each carries a banner at the top saying so.
- **No external requests at runtime.** Fonts are self-hosted and there is no
  analytics, no CDN and no embed. Keep it that way: it is why the site needs no
  cookie banner.
- **Nothing hides the copy, and nothing scripts it.** Every page renders as it
  parses. The language switcher is three plain links to three real pages, so it
  works with scripting off, which is why there is no longer a `<noscript>` rule
  hiding it.
- **Every path in `index.html` is root-absolute**, because the same markup is
  served from `/`, `/de/` and `/fr/`. `404.html` is root-absolute for the
  matching reason: Pages serves it for a bad URL at any depth.
- **`build.py` is standard library only** and prints what it wrote. If it is
  silent about a file, that file was not written.
- **Spacing between sections is padding, never margin** — each section draws
  its own `border-top`, and a margin would let two rules stack.
- **`--muted` is the lightest tone that still clears WCAG AA on both paper
  tones.** Lightening it fails.
